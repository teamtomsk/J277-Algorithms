03 / Be the algorithm · 7 minutes

You choose the next check.

Click the item a binary search should examine next. Use the left middle item when there are two.

The three decisions

  1. Target equals middle? Found.
  2. Target is smaller? Keep the left half.
  3. Target is larger? Keep the right half.

Nothing left?

If the low index moves past the high index, no candidates remain. Report not found.

Always discard the middle item after a non-match. You have already checked it.

Why these numbers?

Each non-matching check roughly halves the candidates. For a non-empty list of n items, the worst case is floor(log₂(n)) + 1 checks.

So 64 needs at most 7; 1,000 needs at most 10. Linear search may check every item.

Why mid + 1 and mid − 1?

The middle item has already been checked. Excluding it makes the range smaller on every non-match. Keeping it can cause a search to get stuck.

What stops this loop?

A match sets found = True. A missing target eventually makes low > high. Either makes the loop condition false. The code then prints the result.

Recall in 30 seconds

Linear: first item, then one by one. Works in any order.

Binary: sorted list, middle item, discard half, repeat.

Missing target: linear reaches the end; binary runs out of candidates.

Efficiency: binary uses fewer checks in the worst case for a large sorted list. Sorting an unsorted list has a cost.

Before opening your notes, explain both algorithms aloud using those four ideas.
